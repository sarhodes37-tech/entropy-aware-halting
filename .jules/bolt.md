## 2024-05-24 - Recursive Generator Expressions vs Iterative DFS in Python
**Learning:** In Python, deeply nested recursive generator expressions like `max((func(x) for x in obj))` create significant performance bottlenecks due to generator instantiation and function call overhead on every level of nesting. They also risk `RecursionError` on large data structures.
**Action:** Replace deep recursive generator aggregations with stack-based iterative Depth-First Search (DFS) patterns to reduce runtime overhead and protect against recursion limits.

## 2024-05-18 - Optimize Scheduler all() Evaluation
**Learning:** Using list comprehensions inside an `all()` function call forces Python to evaluate every item and allocate memory for the full list before checking conditions. This negates `all()`'s short-circuiting ability and wastes CPU/memory, particularly on larger iterables or sliding windows.
**Action:** When passing a comprehension into `all()` or `any()`, always omit the square brackets to use a generator expression instead. This prevents list allocation overhead and takes full advantage of early loop termination (short-circuiting).

## 2025-05-18 - Consolidating Static Word/Entity Dictionary Regexes
**Learning:** In Python, iterating over a list of N individual compiled word-boundary regex patterns (`[re.compile(r"\b" + name + r"\b") for name in dictionary]`) causes N separate regex engine invocations over the target text per detection call.
**Action:** Consolidate static word/entity sets into a single compiled regex pattern with alternation (`re.compile(r"\b(?:" + "|".join(escaped_words) + r")\b")`) to perform a single pass over text, significantly reducing detection latency (~8.4x speedup for dictionary matching).

## 2026-03-31 - Fast-Path Trigger Character & Length Short-Circuiting for Regular Expression Sanitizers
**Learning:** In Python, unconditionally executing multiple compiled regex substitutions (`.sub()`) across string fields in recursive data structures introduces significant CPU overhead even when trigger patterns (like '@', '=', 'bearer', digits) are not present. Using lightweight substring checks (`"@" in s`, `"=" in s`, `len(s) < N`, `re.search(r"\d", s)`) before triggering regex execution yields ~3.6x speedup for string sanitization and ~2.3x overall speedup for log/receipt data sanitization without introducing fragile pattern coupling.
**Action:** Before running complex or multiple `.sub()` operations in hot traversal paths, add fast substring or length guards to short-circuit regex engine invocation when trigger characters are absent.

## 2026-04-01 - Substring Pre-Filter & Synchronized Lowercase Map for Token Rehydration Vaults
**Learning:** In session-scoped mapping vaults like `LocalMappingVault`, iterating through sorted placeholders and unconditionally running `re.Pattern.sub` on target text forces $O(M \cdot L)$ regex passes even when none or few placeholders appear in the text. Because regex word-boundary matching `\btoken\b` requires the token literal to exist as a substring, `if placeholder not in rehydrated: continue` perfectly short-circuits regex execution, accelerating rehydration by 6.0x–18.5x without changing replacement semantics. Furthermore, linear case-insensitive dictionary scans (`for k in dict: if k.lower() == val.lower()`) degrade linearly as vault size grows ($O(N)$); maintaining a synchronized lowercase index `_forward_lower_vault` gives $O(1)$ lookups (~30.7x faster at $N=200$).
**Action:** In token substitution and pseudonymization vaults, always guard regex substitution with literal substring membership checks and index case-insensitive lookups on write.

## 2026-11-01 - Candidate Feature Pre-Extraction and Pre-Intersected Keyword Sets for Pairwise Resolvers
**Learning:** In pairwise clustering algorithms like `SemanticUncertaintyEstimator.estimate()`, repeated feature extraction and set intersection operations (`set_a & NEGATION_WORDS`) across $O(N^2)$ candidate pairs create significant execution and garbage collection overhead even when using an LRU cache. Pre-computing candidate normalization, token sets, and keyword category intersections once per candidate ($O(N)$ instead of $O(N^2)$), coupled with canonical symmetric cache key ordering `(min(i, j), max(i, j))`, lowers peak memory allocation and improves end-to-end `estimate()` throughput without altering clustering, tie-breaking, or disagreement metrics.
**Action:** In $O(N^2)$ pairwise entity/candidate comparison pipelines, always extract and pre-intersect categorical feature sets once per input before entering the pairwise comparison loops.

## 2026-11-02 - Bounded LRU Caching for Recursive Schema Key Regex Inspections
**Learning:** In recursive schema scanners like `PermissionGate._deep_regex_inspection`, repeating regular expression searches on dictionary keys and recurrent short string values (e.g., `policy_id`, `raw_payload`, `endpoint`, `op`) on every submission across pipeline iterations causes substantial redundant regex engine overhead. Because dictionary keys and short configuration tokens repeat thousands of times across requests while arbitrary user input strings may vary widely, memoizing regex inspection with a bounded `@functools.lru_cache(maxsize=4096)` for strings $\le 256$ characters and bypassing the cache for larger text prevents memory bloat while delivering ~4.4x to ~5.5x faster gate evaluation and up to ~48x speedup on repetitive dictionary structures. Importantly, using `isinstance(s, str)` rather than exact type checking `s.__class__ is str` is strictly necessary to prevent security detection bypasses on custom string subclasses.
**Action:** In hot AST or recursive dictionary traversal security gates, bind an LRU cache to short repetitive string checks ($\le 256$ chars) with `isinstance(s, str)` matching while routing unbounded text directly to the regex engine.

## 2026-11-03 - Fast-Path Trigger Character Pre-Checks for Multi-Pattern Sensitivity Detection
**Learning:** In privacy and ingress middleware like `SensitiveDataDetector.detect()`, scanning a text through 10+ compiled regular expressions unconditionally incurs substantial CPU time on clean input (e.g. phone, IP, credit card, file path regexes). Because each pattern requires specific prerequisite tokens or character classes (digits for SSN/IP/cards/phones/IBAN, `@` for emails, `/` or `\` for paths, `bearer` for bearer tokens, `-----BEGIN ` for private keys), checking for these trigger tokens with fast string operations or a single fast digit regex short-circuits up to 9 expensive regex engine scans on clean conversational text (~3.6x speedup, latency dropped from 0.0558ms to 0.0153ms per eval) without altering detection semantics.
**Action:** In multi-pattern scanning pipelines where most inputs are benign, guard specialized regex invocations with lightweight trigger character/substring predicates.

## 2026-11-04 - Fast-Path Destination Trigger Pre-Filtering and Bounded Memoization for Containment URL Scanners
**Learning:** In recursive input argument scanners like `ContainmentGuard._extract_all_strings_and_urls`, evaluating candidate network destination status (`_is_candidate_destination`) on every string argument unconditionally executes full URL parsing (`urllib.parse.urlsplit`), percent-unquoting, control-character scanning, numeric IP parsing, socket conversion, and IDNA normalization via `normalize_destination_host`. Across typical payloads, >95% of strings are normal dictionary keys, identifiers, and labels without destination syntax. Because all valid network destinations (URLs, IPs, host:port, paths, or domains) strictly require at least one structural separator (`/`, `:`, `.`) or digit, pre-filtering with `_DESTINATION_TRIGGER_CHARS = re.compile(r"[/:\.]|\d")` short-circuits full parsing for benign text, delivering a ~5.1x speedup on payload containment checks. Furthermore, pairing this with a bounded `@lru_cache(maxsize=4096)` on `normalize_destination_host` for targets $\le 512$ characters yields >80x speedup for recurrent endpoints without altering parsing semantics or security boundaries.
**Action:** In containment and egress scanning loops that inspect arbitrary strings for URLs/hosts, always short-circuit destination parsing with structural separator/digit trigger pre-checks and memoize canonical host normalization for bounded string lengths.
