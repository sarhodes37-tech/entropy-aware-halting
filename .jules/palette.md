# Palette's Journal - UX & Accessibility Learnings

## 2025-05-20 - Keyboard Accessibility & ARIA in Observatory UI
**Learning:** Icon-only and tab navigation buttons require explicit ARIA labels and roles, and interactive lists (like execution trace items) need proper keyboard event listeners (Enter/Space key support and `tabindex="0"`) alongside `aria-selected` attributes for accessibility.
**Action:** When adding or updating interactive controls in `epistemicos/ui/`, ensure focus indicators, keyboard activation listeners (`keydown` Enter/Space), and semantic ARIA states are present.

## 2026-11-02 - Bidirectional Cross-Surface Investigative Shortcuts
**Learning:** In investigative multi-view dashboards where evidence chains link across different explorer tabs (e.g. Execution Traces and Provenance Explorer), one-way navigation creates dead-ends. Providing symmetric bidirectional navigation shortcuts with descriptive ARIA labels (`aria-label="View provenance records for correlation ..."`) that pre-filter target views allows keyboard and screen reader users to trace audit events seamlessly without losing context.
**Action:** When linking related records across analytical or investigative views, implement symmetric quick-entry navigation triggers that filter the target surface and announce tab transitions via live regions.

## 2026-11-02 - Live Region Announcements & Focus Management for Cross-Tab Filters and Clipboard Operations
**Learning:** When jumping between investigative dashboard tabs using pre-filtered shortcut buttons (such as Overview entry points targeting Execution Traces by status), keyboard users suffer focus abandonment if focus remains on the deactivated tab trigger, and screen reader users lack context on what filter was applied upon landing. Furthermore, clipboard copy actions that only update visual button text (`✓ Copied!`) leave screen reader users without immediate auditory confirmation of success or failure.
**Action:** Always pair cross-tab navigation shortcuts with target focus shifting to the active filter/search control, and route clipboard copy feedback through polite live status announcers (`#a11y-status-announcer`).

## 2026-11-03 - Focus Restoration for Cross-Surface Record Transitions
**Learning:** In split-view and multi-tab investigative dashboards, activating a cross-surface navigation link (such as clicking an Overview table row or "View Related Trace" in Provenance Explorer) switches the active tab and triggers asynchronous record fetching, but leaves focus orphaned on the deactivated surface or `document.body`. Awaiting record selection and programmatically shifting focus to the newly active item (`.trace-item.active`) preserves seamless keyboard context and screen reader position.
**Action:** Always await async record selection on cross-surface jumps and explicitly shift focus to the active record item in the target listbox.

## 2026-11-06 - Live Region Announcements for Keyboard Shortcut Filter Reset
**Learning:** When users clear search query filters using keyboard shortcuts (like `Escape`), the visual input resets and underlying streams re-render, but screen reader users receive zero auditory confirmation that their input was cleared or that the full list has been restored. Emitting polite live region status announcements on Escape key clears (mirroring explicit 'Clear Filters' button behavior) gives screen reader users immediate confirmation without altering DOM focus.
**Action:** Whenever implementing Escape-key query clearance or keyboard shortcuts that reset active filter state, always pair the state reset with an auditory polite live region announcement.

## 2026-11-06 - Polite Live Announcements on Dropdown Filter Selection
**Learning:** In asynchronous single-page dashboards where `<select>` dropdown controls filter stream lists in-place without full-page navigation, visual elements update instantly but screen reader users receive no feedback indicating what filter was applied or that the filter was reset back to all records. Emitting polite live region announcements on select `change` events gives non-visual users confirmation of their active filtering criteria.
**Action:** Always route dropdown filter changes through polite live announcers (`this.announce(...)`), distinguishing between applied filters and resets to 'ALL'.

## 2026-11-06 - Live Region Announcements on Input Backspace and Text Clearance
**Learning:** While clearing filters via explicit buttons or Escape key handlers often triggers live announcements, users frequently clear search filters incrementally by backspacing or selecting all text and deleting it. When the search query transitions from non-empty to empty via standard input events, visual stream lists restore immediately but screen reader users receive zero confirmation that the query was cleared. Detecting non-empty to empty string transitions in input event handlers and emitting polite live region announcements ensures parity for all clearance mechanisms.
**Action:** Whenever listening to real-time search inputs that filter content in-place, announce query clearance when an active query transitions from non-empty to empty.

## 2026-11-07 - Live Region Announcements for Responsive Viewport Drill-Down Navigation
**Learning:** In responsive single-page dashboards where compact/mobile viewports toggle between master-list and detail views via drill-down back buttons (e.g. `Back to Traces` or `Back to Lifecycle`), visual CSS classes and breadcrumbs update immediately, but screen reader users receive zero auditory confirmation of the contextual level change. Pairing drill-down back navigation with polite live region announcements gives non-visual users immediate awareness of the restored view state without disorienting DOM focus shifts.
**Action:** Whenever implementing responsive view level transitions via back navigation controls, route level transitions through polite live announcers (`this.announce(...)`).

## 2026-11-07 - Live Region Announcements for Asynchronous Refresh Operations
**Learning:** In dashboards with asynchronous data refresh triggers, disabling the trigger button and spinning an icon provides immediate visual feedback, but screen reader users receive zero indication that an asynchronous fetch has commenced until the operation resolves or fails. Announcing the initiation of the refresh operation via polite live regions (`this.announce('Refreshing overview metrics...')`) bridges the latency window, giving non-visual users immediate confidence that their click or keypress was registered and work is underway.
**Action:** When triggering async data updates or manual refreshes, pair visual busy indicators (`aria-busy="true"`, disabled states) with an immediate polite live announcement communicating that the refresh has commenced.

## 2026-11-08 - Live Region Announcements for Asynchronous View Load Failures
**Learning:** In single-page analytical dashboards where sub-views load telemetry asynchronously (e.g., Execution Traces, Provenance Explorer, Benchmark Workbench), network failures or API errors render visual error cards with retry buttons, but screen reader users receive no auditory indication that data loading failed or that retry controls are available. Pairing asynchronous fetch failure handlers with polite live region announcements (e.g. `'Failed to load execution traces.'`) gives non-visual users prompt auditory feedback and context to seek out retry actions.
**Action:** Always route asynchronous view loading failures through polite live announcers (`this.announce(...)`) in addition to rendering visual inline error cards and retry triggers.

## 2026-11-08 - Live Region Announcements for Secondary Record Detail Fetch Failures
**Learning:** In master-detail architectures where selecting a master record triggers secondary asynchronous fetches for granular telemetry (e.g. `selectTrace(correlationId)` fetching `/api/trace/${correlationId}`), initial selection announces the attempt (`'Selected execution trace...'`), but downstream fetch failures render an isolated error card in the detail panel without screen reader feedback. Screen reader users are left stranded in silence unaware that detail retrieval failed. Emitting polite live announcements with specific entity context (`'Failed to load trace details for <id>.'`) provides immediate auditory awareness of the secondary failure and prompts keyboard navigation toward the retry control.
**Action:** Always pair secondary asynchronous record detail fetch errors (`renderTraceErrorDetail`) with polite live region announcements identifying the failed record and indicating failure state.

## 2026-11-08 - Live Region Announcements for Master-Detail Lifecycle Stage Selection
**Learning:** In multi-level master-detail interfaces where selecting a master record renders an interactive lifecycle sequence/timeline (e.g. execution trace lifecycle stages), selecting individual stage cards updates downstream evidence inspectors and moves keyboard focus, but screen reader users receive zero auditory confirmation that the inspection stage changed or what event was activated. Announcing stage selection via polite live regions (`Selected lifecycle stage #${seqDisplay} ${type}`) gives non-visual users immediate context and feedback without disrupting focus management.
**Action:** Whenever selecting nested lifecycle sequence stages or sub-event nodes that repopulate inspector panels, route the selection event through polite live announcers (`this.announce(...)`).

## 2026-11-08 - Pre-selection and Inspector Hydration on Cross-Surface Filter Navigation
**Learning:** When jumping between master-detail views via cross-surface shortcuts (e.g. from Trace Explorer to Provenance Explorer via 'View in Provenance'), pre-filtering the target stream without auto-selecting the matching record leaves the detail inspector in an unhelpful empty state (`#provenance-inspector-empty`). Awaiting asynchronous stream hydration and immediately selecting the matching record populates the detail inspector while preserving search input focus and text selection, eliminating dead-ends and extra manual selection steps for keyboard and screen reader users.
**Action:** When navigating across surfaces with filtered queries that map directly to specific records, auto-select the matching record to populate detail inspectors immediately while keeping input focus intact.

## 2026-11-09 - Symmetrical Live Region Feedback for Bidirectional Cross-Surface Shortcuts
**Learning:** When navigating between interrelated analytical views via bidirectional shortcuts (e.g. 'View in Provenance' vs 'View Related Trace'), asymmetric live region feedback breaks user mental models: while forward navigation explicitly announced the target surface and filter criteria, the reverse jump only announced record selection without communicating the surface change. Emitting explicit polite live region announcements for the target view upon activating reverse cross-surface shortcuts restores bidirectional feedback parity for screen reader users.
**Action:** In bidirectional cross-surface navigation patterns, ensure both directions emit explicit live announcements communicating surface transition and correlated identifier.

## 2026-11-09 - Auditory Feedback Parity for Tabular Cross-Surface Row Activation
**Learning:** In dashboard overviews where summary tables offer clickable rows that jump across analytical views and select records (such as clicking an Overview operational stream row to inspect an execution trace), visual navigation occurs immediately and keyboard focus shifts to the target listbox, but screen reader users lack context on what just happened. Emitting an explicit polite live region announcement communicating the destination surface and entity identifier (`Navigated to Execution Trace Explorer (Trace: <id>)`) provides immediate auditory awareness that aligns with standalone button shortcuts.
**Action:** Whenever implementing clickable table rows that perform cross-surface navigation, always emit an explicit polite live region announcement identifying the destination view and selected entity.

## 2026-11-09 - Visual Hierarchy & Outcome Elevation in Analytical Detail Inspectors
**Learning:** In technical master-detail dashboards (such as Benchmark Workbench), presenting all telemetry attributes in a flat key-value list dilutes high-stakes evaluation verdicts (like TC/FC/TR/FR classifications and surprisal rollback decisions) among technical digests and run IDs. Elevating the decision verdict into a dedicated hero banner with classification-coded semantic left borders, prominent status badges, and compact metric pill strips (latency, tokens, expected-to-actual outcome progression) allows users to immediately absorb evaluation outcomes while cleanly delegating granular artifact hashes to a separate verification block.
**Action:** When designing analytical detail views, elevate decision outcomes into a dedicated verdict hero bar and group technical artifact hashes into a distinct provenance column.

## 2026-11-10 - Full Record Export Parity Across Master-Detail Analytical Surfaces
**Learning:** In multi-view investigative observability applications where each tab inspects different lifecycle artifacts (Traces, Provenance records, Benchmark cases), providing quick-copy actions for specific IDs without a full record export creates friction when incident responders need to share or log complete evidence payloads. Offering symmetric 'Copy Record JSON' / 'Copy Trace JSON' actions across all inspector headers with accessible ARIA labels (aria-label="Copy full JSON payload for trace ...") and polite live region clipboard announcements provides consistent, predictable data portability for keyboard and screen reader users alike.
**Action:** When designing analytical master-detail inspection headers, always pair identifier copy shortcuts with complete record payload export buttons that route through accessible live region announcers.

## 2026-11-10 - Primary Entity Identifier Action Parity Across Inspector Surfaces
**Learning:** In analytical dashboards where multiple master-detail surfaces present related telemetry artifacts, providing quick-copy buttons for primary entity identifiers on some surfaces (e.g., 'Copy Correlation ID' in Trace Explorer, 'Copy Case ID' in Benchmark Workbench) while omitting it on others (e.g., Provenance Explorer only offering 'Copy Record JSON') creates user friction and broken mental models. Supplying symmetric primary entity identifier copy actions ('Copy Event ID') in inspector headers alongside payload exports gives keyboard and screen reader users direct, accessible one-click access to critical entity keys.
**Action:** When designing inspector headers across interrelated surfaces, ensure primary entity identifier copy buttons ('Copy <Entity> ID') are consistently available alongside full payload exports with matching accessible ARIA labels and feedback announcers.

## 2026-11-11 - Focus Management for Analytical Master-Detail Record Selection
**Learning:** In master-detail layouts where selecting an item from a listbox dynamically populates an inspector surface (such as selecting a test case in Benchmark Workbench), leaving focus on the deactivated or selected list item requires keyboard and screen reader users to manually tab through trailing items to access the newly rendered inspector. Shifting programmatic focus to the populated inspector region (`#benchmark-case-content` with `tabindex="-1"`, `role="region"`, and descriptive `aria-label`) immediately connects the user's intent to the detailed evaluation breakdown, verdict hero, and action buttons.
**Action:** Whenever selecting records in master-detail exploratory views dynamically renders detail or inspector panels, explicitly manage focus by transferring it to the populated inspector container with appropriate region semantics.

## 2026-11-11 - Region Semantics and Programmatic Focus Parity in Stream Inspectors
**Learning:** In multi-view master-detail exploratory workspaces, omitting region landmark semantics (`role="region"` and `aria-label`) and programmatic focus transfer on inspector containers (e.g. Provenance Explorer's `#provenance-inspector-content`) creates inconsistent accessibility across similar views. When keyboard and screen reader users select an event from the recorded stream listbox, lack of focus transfer strands their cursor on the list item, forcing manual tab navigation past dozens of trailing stream entries to reach inspector action controls (such as 'View Related Trace' or 'Copy Event ID'). Adding `tabindex="-1"`, `role="region"`, and an explicit `aria-label` combined with `contentDiv.focus()` upon dynamic population brings Provenance Explorer into complete a11y parity with Benchmark Workbench.
**Action:** Always ensure all analytical detail inspector containers across the application expose region landmark semantics and receive programmatic focus immediately upon record selection.
